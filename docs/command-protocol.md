# BLE 命令协议参考

## 概述

所有命令通过 BLE 特征值 (UUID: `00002446-0000-1000-8000-00805F9B34FB`) 传输。

- 命令格式：`[2字节命令码 (大端)] + [可选数据]`
- 响应格式：`[状态字节] + [命令码低字节] + [数据]`
  - `0x00` = 成功
  - `0xFF` = 错误
  - `0xFE` = 需要认证 (加密模式)

当加密启用时，除 `0x0050` (AUTHENTICATE) 和 `0x0043` (FIRMWARE_VERSION) 外，所有命令和响应均使用 AES-128-CCM 加密。

## 命令列表

### 0x0043 - 固件版本查询

无需认证。

**请求**：`[0x00, 0x43]`

**响应**：
```
[0x00] [0x43] [major] [minor] [sha_len] [sha_hex...]
```
- `major`: 主版本号
- `minor`: 次版本号
- `sha_len`: Git SHA 十六进制字符串长度 (最大 40)
- `sha_hex`: Git SHA 十六进制字符串

---

### 0x0050 - 认证

**请求**：`[0x00, 0x50] + [认证数据]`

**响应**：
```
成功: [0x00] [0x50] [会话数据...]
失败: [0xFF] [0x50]
```

---

### 0x0040 - 读取配置

**请求**：`[0x00, 0x40]`

**响应**：分多个块返回，每块最多 100 字节。
```
[0x00] [0x40] [chunk_number_lo] [chunk_number_hi] [可选: total_len_lo total_len_hi] [data...]
```
- 第一个块包含 2 字节总长度
- 后续块仅包含数据

---

### 0x0041 - 写入配置

**请求**：
```
小配置 (< 200 字节):
  [0x00, 0x41] + [config_data]

大配置 (>= 202 字节):
  [0x00, 0x41] + [total_size_lo] [total_size_hi] + [first_chunk_data]
```

**响应**：
```
成功: [0x00] [0x41] [0x00] [0x00]
失败: [0xFF] [0x41] [0x00] [0x00]
```

大配置写入后，使用 0x0042 继续传输剩余块。

---

### 0x0042 - 配置分块续传

**请求**：`[0x00, 0x42] + [chunk_data]`
- 每块最大 200 字节
- 最多 20 块

**响应**：
```
中间块确认: [0x00] [0x42] [0x00] [0x00]
最后块 (写入完成):
  成功: [0x00] [0x42] [0x00] [0x00]
  失败: [0xFF] [0x42] [0x00] [0x00]
```

---

### 0x0044 - 读取 MSD

**请求**：`[0x00, 0x44]`

**响应**：
```
[0x00] [0x44] [msd_payload_16_bytes]
```

MSD 结构 (16 字节)：
| 偏移 | 长度 | 说明 |
|------|------|------|
| 0-1 | 2 | Company ID (0x2446) |
| 2-12 | 11 | dynamicreturndata (按钮/传感器状态) |
| 13 | 1 | 温度编码值 |
| 14 | 1 | 电池电压低字节 |
| 15 | 1 | 状态字节 |

温度解码：`temp_C = byte / 2.0 - 40.0`

电池电压解码：
```
voltage_10mv = (status_byte & 0x01) << 8 | voltage_low_byte
voltage_V = voltage_10mv * 10 / 1000.0
```

---

### 0x0070 - 直接写入开始

**请求**：
```
无压缩: [0x00, 0x70]
压缩:   [0x00, 0x70] + [decompressed_size_4bytes_LE] + [可选初始压缩数据]
```

**响应**：
```
成功: [0x00] [0x70]
失败: [0xFF] [0xFF]
```

---

### 0x0071 - 直接写入数据

**请求**：`[0x00, 0x71] + [image_data]`

**响应**：
```
成功: [0x00] [0x71]
失败: [0xFF] [0xFF]  (缓冲区满)
```

当写入数据量达到面板总字节数时，自动触发 0x0072 结束流程。

---

### 0x0072 - 直接写入结束

**请求**：
```
[0x00, 0x72] + [可选参数]
  参数[0]: 刷新模式 (0=FULL, 1=FAST)
  参数[1-4]: 新 etag (可选, 大端)
```

**响应**：
```
ACK:   [0x00] [0x72]
成功:  [0x00] [0x73]  (刷新完成)
超时:  [0x00, 0x74]  (刷新超时)
```

---

### 0x0076 - 局部更新开始

**请求**：
```
[0x00, 0x76] + [flags] + [old_etag_4B] + [new_etag_4B]
            + [x_2B] + [y_2B] + [width_2B] + [height_2B]
            + [可选初始流数据]
```

flags:
- bit 0: 压缩模式

**响应**：
```
成功: [0x00] [0x76]
失败: [0xFF] [0x76] [error_code] [0x00]
```

错误码：
| 值 | 说明 |
|----|------|
| 0x01 | etag 不匹配 |
| 0x03 | 矩形超出屏幕范围 |
| 0x04 | 矩形未 8 像素对齐 |
| 0x05 | 不支持的 flags |
| 0x06 | 流数据错误 |
| 0x07 | 面板不支持局部更新 |

---

### 0x0073 - LED 激活

**请求**：`[0x00, 0x73] + [led_data]`

---

### 0x0075 - 蜂鸣器激活

**请求**：`[0x00, 0x75] + [buzzer_data]`

频率索引映射：0 = 静音，1-255 线性映射到 400Hz - 12000Hz。

---

### 0x000F - 重启

**请求**：`[0x00, 0x0F]`

设备立即重启。

---

### 0x0051 - 进入 DFU 模式

**请求**：`[0x00, 0x51]`

设备进入 DFU (固件升级) 模式。仅在加密未启用时可用。
